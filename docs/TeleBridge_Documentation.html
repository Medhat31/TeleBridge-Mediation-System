3. Dynamic FTP Container Lifecycle

The most complex part of TeleBridge is how it provisions its own infrastructure. When an Admin creates a new "Node" in the Web UI, the Java Engine detects it and automatically launches a new Docker Container specifically for that Node using the Host's Docker Socket.

Note over Engine, FTP: Engine dynamically binds the Host's "node_volumes/UPSTREAM/28"
directory into the new container's /home/user/share folder. end Admin->>UI: Deletes Node via Dashboard UI->>DB: DELETE FROM Nodes Engine->>DB: Fetches active nodes Engine->>Docker: Detects orphan container "telebridge_upstream_28" Engine->>Docker: Runs: "docker rm -f telebridge_upstream_28" Docker->>FTP: Kills & Removes Container

4. CDR Generator Operation

The Python CDR Generator simulates network traffic. It actively polls the database to discover which Upstream Nodes are currently marked as "active", and only generates CDR files inside the specific mounted host volumes belonging to those active nodes.

sequenceDiagram autonumber participant DB as PostgreSQL DB participant Gen as CDR Generator (Python) participant FS as Host Filesystem (node_volumes/) loop Every 15 seconds Gen->>DB: 1. SELECT node_id, node_name FROM Nodes WHERE type='UPSTREAM' AND is_active=true alt No Active Nodes DB-->>Gen: Returns Empty List Note over Gen: Logs: "No active nodes found." else Active Nodes Found DB-->>Gen: Returns Node ID: 28, Name: MSC_Cairo Note over Gen: 2. Generates 50-100 fake Hex TLV Records Gen->>FS: 3. Writes records to the active node's directory:
node_volumes/UPSTREAM/28/MSC_20260721.tlv end end
